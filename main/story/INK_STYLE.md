# Стандарт написания Ink для «АВОСЬ»

Этот файл — спецификация под нашу реализацию Ink в Defold. Всё, что здесь
перечислено, движок понимает и исполняет. Всё, что сюда не вошло, — либо
игнорируется, либо ломает сборку. Если даёшь истории редактировать нейросети —
**скопируй этот файл в системный промпт целиком**.

Движок: `dialogue_manager_ink.lua` + `scene_controller.lua`. Исходный Ink-ранером
занимается `defold-ink`; наш слой поверх него — только теги (`#`) и VAR.

---

## 1. Скелет файла

```ink
// Комментарий (две косые черты). Можно в начале строки или в конце.
// Переменные игрока выставляет Lua ДО первого continue (не трогай их сам):
VAR mc_gender = "male"
VAR mc_name   = "Артём"
VAR npc_name  = "Мила"

// Драм-флаги главы — счётчики для разветвления. Читай, прибавляй, не сбрасывай:
VAR TRUST   = 0
VAR INSIGHT = 0
VAR SYNC    = 0

// Любые собственные VAR'ы для локальной логики сюжета — ОК:
VAR coffee_drunk = false
VAR newspaper_kept = false

-> wake_intro   // стартовый knot обязателен

=== wake_intro
# bg:bg_bedroom_01 # speaker:mc
Текст параграфа. Каждый абзац — отдельный «клик» игрока.
-> choose_character
```

- Файл всегда начинается с `VAR`-блока, дальше `-> start_knot`, дальше сами
  knot'ы.
- Knot: `=== name` (три знака равенства, пробел, имя без пробелов и кириллицы).
  Имя — латиница/цифры/подчёркивания.
- Конец ветки: `-> ИмяСледующегоKnot'а` или `-> DONE` (тупик), или `-> END` (конец
  истории).

---

## 2. Параграфы и теги

Каждый абзац в Ink — это один шаг, показываемый игроку. Теги (`#`) идут
**на той же строке** либо **сразу перед** текстом и применяются к этому
параграфу.

```ink
# bg:bg_kitchen # sfx:coffee_brew # speaker:mc
Горький, терпкий. Голова начинает работать.
```

Теги разделяются пробелом+`#`. Порядок не важен. Регистр имеет значение
(`bg`, не `BG`).

### Висячие теги в конце knot'а

Если после последнего параграфа стоят голые теги и `-> DONE`, они
применяются **после того как игрок прочитает всё**. Так удобно вешать
возврат в сцену:

```ink
=== take_phone
# speaker:mc
Холодный. Ладно. Нашёлся — уже хорошо.

# flag:has_phone=true
# return_to_scene
-> DONE
```

## 3. Поддерживаемые теги

### Вид и звук

| Тег | Пример | Что делает |
|---|---|---|
| `bg:IMAGE` | `# bg:bg_metro` | Меняет фон. `bg:none` — убрать фон. Картинка должна существовать в атласе `backgrounds.atlas`. |
| `color:R,G,B` | `# color:0.1,0.1,0.15` | Тинт фона (0…1). Используется для подсветки. |
| `speaker:ID` | `# speaker:mc` / `# speaker:npc` / `# speaker:none` / `# speaker:Аня` | Меняет «имя говорящего» в табличке. `mc` / `npc` резолвятся в `mc_name`/`npc_name`. `none` — без таблички (нарратор). |
| `sfx:NAME` | `# sfx:phone_pickup` | Одноразовый звук. Файл должен быть в `sounds/sfx/`. |
| `shake:I,D` | `# shake:0.2,0.5` | Тряска экрана. `I` — сила (0…1), `D` — длительность сек. |
| `pulse:D,R,G,B` | `# pulse:0.8,0,255,0` | Мерцание цветом (RGB 0…255). |

### Состояние игры

| Тег | Пример | Что делает |
|---|---|---|
| `flag:NAME=VAL` | `# flag:has_phone=true` | Пишет в `game_state`. Читается из `scenes.lua` через `gs.get_flag(...)`. Значения: `true`/`false`/число/строка. |
| `item:add:ID` | `# item:add:mug` | Добавить предмет в инвентарь. |
| `item:remove:ID` | `# item:remove:mug` | Убрать. |
| `quest:start:ID` | `# quest:start:make_coffee` | Активировать квест (статус `active`). |
| `quest:done:ID` | `# quest:done:go_to_office` | Закрыть (статус `done`). |
| `quest:fail:ID` | `# quest:fail:reply_anya` | Провалить. |

⚠️ **`quest:complete` НЕ работает**. Используй `quest:done`.

### Телефон

| Тег | Пример | Что делает |
|---|---|---|
| `sms:add:CONTACT:TEXT` | `# sms:add:anya:"PATCH temporal_sync.module"` | Добавить SMS в приложение «Сообщения». Кавычки вокруг текста — опционально, но с ними безопаснее (двоеточия внутри текста не поломают парсинг). |
| `note:add:TITLE:BODY` | `# note:add:Коммит:"хеш 03:47"` | Добавить заметку. |
| `phone:close` | `# phone:close` | Выйти из сцены телефона обратно в место, откуда его открыли. Используется только в knot'е `phone_close`. |

### Сцены (point-and-click)

| Тег | Пример | Что делает |
|---|---|---|
| `explore:SCENE_ID` | `# explore:apartment_hub` | **Отдать управление в point-and-click**. Ink ждёт. Используется в конце вводного knot'а: «выпасть» в сцену, где игрок кликает по hotspot'ам. Эквивалент `goto_scene:`. |
| `goto_scene:SCENE_ID` | `# goto_scene:kitchen` | То же, другое имя. |
| `return_to_scene` | `# return_to_scene` | Вернуться в **предыдущую** point-and-click сцену (после короткого ink-монолога, вызванного hotspot'ом). Ставь в самом конце knot'а. |

## 4. VAR против `# flag:` — ЧИТАЙ ВНИМАТЕЛЬНО

В Ink есть **две параллельные системы состояния**:

1. **`VAR` / `~ присваивание`** — внутренние переменные Ink. Видны в
   `{условиях}` и в `{выражениях}` внутри ink-файла. **НЕ видны** в
   `scenes.lua` и в `game_state`.
2. **`# flag:X=Y`** — пишет в Lua-состояние (`game_state`). Видно в
   `scenes.lua` через `gs.get_flag("X")`. **НЕ видно** из ink-условий.

### Правило

- Нужно ветвить **внутри истории** (`{coffee_drunk: ...}`) — используй VAR.
- Нужно открыть/закрыть **hotspot или hide объект на сцене** — используй флаг.
- Нужно И то, И то — **дублируй**:

```ink
~ coffee_drunk = true
# flag:coffee_drunk=true
```

Это обязательная договорённость. Не полагайся на «движок сам подтянет» — не
подтянет.

### Нейминг

- `has_X` — предмет у игрока (`has_phone`, `has_mug`)
- `X_seen` — сцена/реплика уже была (`kitchen_intro_seen`, `sms_anya_read`)
- `need_X` — промежуточная цель активирована (`need_mug_for_coffee`, `need_phone`)
- `X_drunk` / `X_done` / `X_active` — результат действия (`coffee_drunk`,
  `left_apartment`)
- `_underscore_в_начале` — служебные, задаются движком (`_phone_return_scene`)

## 5. Выборы

```ink
* [Проверить уведомления]
    ~ INSIGHT = INSIGHT + 1
    # speaker:none
    Открываю приложение. Три патча в очереди.
    -> metro_continue

* [Отложить]
    ~ SYNC = SYNC + 1
    # speaker:mc
    Потом. Сейчас не до этого.
    -> metro_continue
```

- `*` — одноразовый выбор (пропадает после клика). `+` — многоразовый.
- Текст выбора — в `[квадратных скобках]`, он **не** показывается как
  реплика, только как кнопка.
- Внутри тела выбора: `~` (присваивание VAR), теги, реплики, `->`.
- Условный выбор: `* {SYNC >= 2 && INSIGHT >= 2} [<<Синхронизировать ритм>>]`.
  Если условие `false` — пункт скрыт.

### «Назад»-выборы в телефоне

У нас типовой паттерн для knot'ов вроде `phone_tasks`, `phone_notes`:

```ink
* [Назад]
    # return_to_scene
    -> DONE
```

Движок это корректно отработает — вернёт в `phone_home`.

## 6. Гендер и имена

Короткая форма внутри строки:

```ink
Проснул{mc_gender == "female":ась|ся}?
В отражении — {mc_gender == "female":женское|мужское} лицо.
Я не замети{mc_gender == "female":ла|л}.
```

- Внутри `{...:A|B}`: если условие истинно — `A`, иначе — `B`.
- Для пустой ветки оставь пусто: `замети{mc_gender == "female":ла|}` (мужской
  вариант пустой, т.е. слово просто «заметил»).

Имена подставляются автоматически: `{mc_name}`, `{npc_name}`. Ink-сторона
синхронизирует их с Lua при выборе пола.

---

## 7. Условные блоки

```ink
{coffee_drunk:
    Кофеин ещё действует. Руки не дрожат. # speaker:mc
}
{not coffee_drunk:
    Голова немного тяжёлая. # speaker:mc
}
```

- Блок исполняется если условие истинно.
- Внутри блока можно ставить теги и `~`-присваивания.
- Можно и в одну строку: `{phone_active: Телефон вибрирует.}`

## 8. Интеграция со сценами point-and-click

**Сцена** — это `scenes.lua` (отдельный файл). В ней описываются фон и
hotspot'ы: кликабельные прямоугольники. Каждый hotspot может:

- перейти в другую сцену (`goto_scene`),
- поставить флаг / выдать предмет,
- **запустить ink-knot** (`ink_knot: "knot_name"`).

### Паттерн «короткий монолог из сцены»

```ink
=== take_mug
# speaker:none
В ящике — одна чистая кружка.

# speaker:mc
Подойдёт. Забираю с собой.

# flag:has_mug=true
# return_to_scene
-> DONE
```

Движок:
1. Выходит из сцены, скрывает hotspot'ы.
2. Прыгает в `take_mug`, показывает параграфы.
3. По последнему клику применяет `# flag:has_mug=true` и возвращает игрока
   в ту же сцену, где hotspot был нажат. Сцена перерисуется — hotspot
   «ящик» пропадёт (если у него `condition = not has_mug`).

### Паттерн «выход из сюжетной сцены в point-and-click»

В конце длинной вводной сцены:

```ink
=== wake_after_choice
# bg:bg_bedroom_03 # speaker:mc
...длинный монолог...
-> apartment_hub

=== apartment_hub
# bg:bg_apartment # explore:apartment_hub # speaker:mc
Коридор. Тихо.
-> DONE
```

Тег `# explore:apartment_hub` отдаёт управление `scene_controller` на сцене
`apartment_hub`. Ink-сторона переходит в состояние «ждёт».

## 9. Квесты

```ink
# quest:start:make_coffee    // в начале главы, явно стартуем
...
# quest:done:make_coffee     // когда кофе выпит
```

- Стартуй **явно** (`quest:start`) — иначе `quest:done` без старта может
  проигнорироваться.
- ID — латиница/подчёркивания (`make_coffee`, `reply_anya`, `go_to_office`).
- Текст квеста для UI лежит в `main/scripts/quests_catalog.lua` (если его
  нет — спроси у разработчика, куда добавлять).

## 10. Драм-флаги TRUST / INSIGHT / SYNC

Это три счётчика эмоциональной оси. Их можно:

- Увеличивать: `~ TRUST = TRUST + 1`
- Проверять в условных выборах: `* {SYNC >= 2 && INSIGHT >= 2} [ветка]`
- Проверять в блоках: `{INSIGHT > 3: текст}`

Диапазон: практически любой, но держи инкременты маленькими (±1, ±2). На
конец главы ожидается сумма 3–8 по каждой оси.

---

## 11. Чеклист «ink готов к загрузке»

Перед тем как закоммитить новый `.ink`:

- [ ] Все knot'ы начинаются с `=== name` (имя latin_snake_case).
- [ ] Есть `-> start_knot` в самом верху после VAR-блока.
- [ ] Все ветки заканчиваются либо `-> name`, либо `-> DONE`, либо `-> END`.
- [ ] Каждому new фону `bg:NAME` соответствует картинка в `backgrounds.atlas`
      (если её нет — попроси добавить, иначе фон станет чёрным).
- [ ] Все `sfx:NAME` существуют в `sounds/sfx/` (иначе будет silent fail).
- [ ] `{mc_gender == "female":ж|м}` проверен по всем репликам MC-а (нет
      просто `вернулся` без форки).
- [ ] Не использовал `quest:complete` — только `quest:start`/`done`/`fail`.
- [ ] VAR'ы, на которые завязаны hotspot'ы в `scenes.lua`, продублированы
      `# flag:X=VAL`.
- [ ] Тестовая компиляция через inklecate прошла без ошибок.

## 12. Что не поддерживается

Чтобы не тратить время:

- `EXTERNAL` функции, `LIST` — игнорируются (парсер пропустит, но ничего
  не сделает).
- Вложенные stitches (`= substitch`) — можно писать, но полагайся только на
  `===`-knot'ы как на «адресуемые» точки.
- Теги на VAR-строках — ignored.
- `# TODO`, `# XXX`, любые «заметки разработчика» в тегах — игнорируются
  (можно использовать для себя — движок их не трогает).
- Tunnels (`-> tunnel ->`) — технически работают (это чистый Ink), но мы
  ими не пользуемся; не рекомендую.

## 13. Мини-пример полного knot'а

```ink
=== use_coffee_machine_with_cup
# bg:bg_kitchen # speaker:none # sfx:coffee_brew
Кружка встаёт под носик. Машина оживает. Тёмная струйка наполняет кружку.

# speaker:mc
Вот. Теперь правильно.

# speaker:mc
Горький, терпкий. Голова начинает работать. Теперь телефон. Без него дверь не открыть.

~ coffee_drunk = true
~ SYNC = SYNC + 1
~ morning_choice = "coffee"

# flag:coffee_drunk=true
# flag:need_phone=true
# quest:done:make_coffee
# quest:start:find_phone
# return_to_scene
-> DONE
```

Этот knot:
- Меняет фон и играет звук варки.
- Показывает три реплики (два клика игрока).
- Ставит внутренний VAR `coffee_drunk` для ink-условий.
- Дублирует в Lua-флаг для hotspot'а «Выйти» в квартире.
- Закрывает один квест, открывает следующий.
- Возвращает в сцену, где была кофемашина (kitchen).
