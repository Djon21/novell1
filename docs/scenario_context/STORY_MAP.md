# Story Map

Этот документ — карта сюжета и структуры ink-файлов. Используй чтобы понять
**что уже написано** и **в каком файле живёт** какая часть истории, не
загружая все ink-файлы сразу.

> Для **точного списка существующих knot'ов** (имена + аннотации) смотри
> `PROJECT_INVENTORY.md` — он автогенерится из реального кода. Этот документ
> описывает нарративную структуру и логику дня-за-днём.

---

## Структура ink-файлов

Ink-файлы лежат в `main/story/chapters/`. Структура **локация × день**:
квартира — один файл на все дни (точка времени), остальные локации —
по файлу на каждую пару (локация, день).

### Системные файлы

| Файл | Содержание |
|---|---|
| `00_bootstrap.ink` | Стартовые VAR, начальная подготовка, **падежные формы имён** (`mc_name_*`, `npc_name_*`). Глобальные начальные значения. |
| `10_apartment.ink` | **Квартира во все дни всех итераций.** Утра/вечера каждого дня, выбор персонажа (sunday), переходы между днями через сон, dream sequences, iter 2+ свободные визиты. Управляет переключателем `current_day`. |

### Локации × день (`chapters/locations/`)

| Файл | Содержание |
|---|---|
| `park_sunday.ink` | Парк в воскресенье: arc встречи с NPC + все sunday-хотспот-реакции. |
| `cafe_sunday.ink` | Кафе в воскресенье: arc встречи + хотспоты. |
| `shop_sunday.ink` | Магазин 24/7 в воскресенье: pre-date / with-npc сцены + хотспоты полок. |
| `viewpoint_sunday.ink` | Смотровая в воскресенье. |
| `bar_sunday.ink` | Бар Maybe в воскресенье (минимальный хаб). |
| `*_monday.ink`, `*_tuesday.ink` | Заглушки до миграции. Понедельник/вторник пока в legacy-файлах. |

**Правила:**
- **Одна локация × один день = один файл.** Хочешь сцену "парк во вторник" — она лежит **только** в `park_tuesday.ink`.
- **Iter 2+ контент того же дня** — внутри того же файла под условием `iteration_number >= 2`. Не плодить параллельные файлы.
- Видимостью хотспотов в зависимости от дня управляет `visible_when` в `scenes.lua`, не сам ink.
- Если хотспот живёт на нескольких днях с разной реакцией — заводи `<location>_common.ink` с knot-диспетчером, который сам ветвится по `current_day`. **Лениво** — только когда реально нужно.

## Как выбирать файл для задачи

- Сцена в квартире (любой день) → `10_apartment.ink`
- Сцена в конкретной локации в конкретный день → `locations/<location>_<day>.ink`
- Сцена связана с телефоном → `92_phone_sms.ink` / `93_phone_messenger.ink`
- Реакция на предмет → `91_inventory_actions.ink`
- Что-то про имена / падежи / пол → `00_bootstrap.ink` + `10_apartment.ink`

**Не создавай новый ink-файл для каждой маленькой сцены.** Новый файл — только если появляется новая пара (локация, день), либо новый сервисный модуль.

## Стабильность knot-имён

Имена `=== knot_name ===` должны быть стабильны, потому что на них ссылаются:

- другие ink-переходы (`-> knot_name`)
- Lua-хотспоты (`action = { type = "ink_knot", knot = "..." }` в `main/data/scenes/*.lua`)
- Телефон (`# phone:app:NAME` + соответствующие knot)
- Карта (`# map:hub:KNOT`)
- Scene characters (`# scene_char:show:...:...` с click-action)
- Dev-jump / checkpoint система
- Документация и SOURCE_FILE_PACKS

При переименовании knot'а **сначала** ищи все ссылки на старое имя (grep по `'<knot_name>'` во всём `main/`).

## Нарративная структура (день за днём)

### Воскресенье: квартира

Старт игры. Здесь:
- Выбор персонажа (Артём ↔ Мила, мужской/женский MC)
- Базовый онбординг (как работают хотспоты, инвентарь, телефон)
- Первые сообщения, первое SMS-взаимодействие
- Подготовка к выходу (умыться, кофе, забрать телефон)

Локации: спальня → ванная → кухня → коридор → выход.

**Важное**: выход из квартиры приводит к актуальной карте через телефон, а не к старой карте.

### Воскресенье: встреча

После квартиры — выбор места встречи через карту. Возможные точки: кафе, парк, магазин, смотровая, бар, архив.

Свидание не просто диалоговая сцена. Здесь игрок начинает чувствовать:
- Ритм мира
- Реакции NPC
- Первые лёгкие странности (но **без подсветки петли** — никаких «дежавю», сбоев времени, прямого осознания)

### Понедельник: дом и дорога

Утро понедельника, сборы. Более «собранный» деловой блок после личного воскресенья.

Задачи:
- Поднять игрока утром
- Привести к выходу из дома
- Связать личное настроение с рабочей линией
- Подготовить офисный конфликт

### Понедельник: офис

Рабочий кейс, который ощущается как часть общей темы AVOS: **решения принимает система, последствия остаются человеческими**.

Важные локации: рабочее место, переговорная.

Здесь — выбор который **нельзя откатить логом**. Реальный сюжетный поворот понедельника.

### Вторник: дом

Последствия понедельника. Игрок уже не просто живёт обычный день — целенаправленно ищет след.

Задача блока: перевести героя из режима **реакции** в режим **расследования**.

### Вторник: расследование

Игрок идёт по следам, проверяет локации, собирает смысловые куски.

Этот блок плотно работает с картой, телефоном, хотспотами и предметами. При написании сюда — особенно внимательно с флагами и доступностью POI на карте.

### Крыша и финал

Финальный блок закрывает текущую главу/петлю. Перевод в завершение (меню / следующую итерацию) через актуальный сценарный механизм, не через случайный goto.

## Подсистемы

### Телефон в нарративе

Телефон — **не отдельный бонусный экран**, а часть повествования. Через него идут SMS, мессенджер, карта, заметки. Может появляться когда игрок находится:
- В диалоговом окне (overlay поверх dialog)
- В режиме исследования (overlay поверх scene)

Phone-теги в ink: `# phone:app:NAME`, `# phone:map`, `# sms:add:...`, `# msg:add:...`. См. `INK_TAGS.md`.

### Инвентарь в нарративе

Инвентарь используется для **осмотра** и **применения предметов на хотспотах**. При armed-state (игрок выбрал предмет с verb `use`) над сценой появляется баннер «Используй X на цели».

Логика armed banner намеренно отделена от обычных HUD-кнопок чтобы случайный клик по баннеру не открыл меню. См. `INVENTORY_SYSTEM.md` для полной цепочки.

### Сцены исследования (exploration mode)

Цикл «ink → exploration → ink»:

```
1. Ink показывает реплику и ставит флаги
2. # explore:scene_id или хотспот в финале — перевод в exploration
3. Игрок видит фон + хотспоты, кликает
4. Hotspot.action: type="ink_knot" → return в ink, или type="goto_scene" → другая сцена
5. Knot ставит флаги, ведёт диалог, возвращает через # return_to_scene
```

См. `LOCATIONS_GUIDE.md` для деталей структуры хабов.
