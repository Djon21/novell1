# Current State And Flags

Этот документ описывает не все переменные проекта, а те группы состояния, которые чаще всего важны при написании сцен и хабов.

## Где живёт состояние

В проекте есть несколько уровней состояния:

- Ink `VAR` - сценарные переменные, отношения, счётчики, выбранные варианты.
- Game state flags - флаги рантайма, которые читают сцены, хотспоты, телефон и инвентарь.
- Inventory items - предметы игрока.
- Phone state - прочитанные/доступные SMS, мессенджер, приложения.
- Map state - доступные и заблокированные точки карты.

Если GPT пишет только текст сцены, чаще всего достаточно Ink `VAR` и тегов. Если GPT помогает с хабом, нужны game flags и scene Lua.

## Важные сюжетные параметры

- Выбранный персонаж игрока.
- Имя/форма обращения игрока.
- День истории: воскресенье, понедельник, вторник.
- Уровень доверия к NPC.
- Уровень наблюдательности/понимания происходящего.
- Синхронизация или близость к петле/системному сбою.

Точные имена переменных надо проверять в текущем Ink-файле перед правкой. Не стоит придумывать новые `VAR`, если уже есть похожие.

## Падежные формы имён

В Ink доступны не только `mc_name` и `npc_name` в именительном падеже, но и заранее подготовленные формы для русского текста.

Переменные игрока:

- `mc_name` - именительный: Артём / Мила
- `mc_name_gen` - родительный: Артёма / Милы
- `mc_name_dat` - дательный: Артёму / Миле
- `mc_name_acc` - винительный: Артёма / Милу
- `mc_name_ins` - творительный: Артёмом / Милой
- `mc_name_prep` - предложный: Артёме / Миле

Переменные NPC:

- `npc_name` - именительный: Мила / Артём
- `npc_name_gen` - родительный: Милы / Артёма
- `npc_name_dat` - дательный: Миле / Артёму
- `npc_name_acc` - винительный: Милу / Артёма
- `npc_name_ins` - творительный: Милой / Артёмом
- `npc_name_prep` - предложный: Миле / Артёме

Используй падежную форму вместо `{npc_name}` или `{mc_name}`, если имя стоит внутри фразы не в именительном падеже.

Примеры:

- правильно: `{npc_name_gen} нигде не видно.`
- неправильно: `{npc_name} нигде не видно.`
- правильно: `написать {npc_name_dat}`
- неправильно: `написать {npc_name}`
- правильно: `рядом с {npc_name_ins}`
- неправильно: `рядом с {npc_name}`

Эти формы задаются в `00_bootstrap.ink`, уточняются при выборе персонажа в `01_apartment.ink` и синхронизируются в `dialogue_manager_ink.lua`, чтобы старые сохранения и восстановление состояния не оставляли неправильные дефолтные формы.

## Частые квесты и флаги

В проекте встречаются такие сюжетные задачи:

- `find_phone` - найти/взять телефон.
- `make_coffee` - приготовить кофе.
- `reply_npc` - ответить NPC в телефоне.
- `meet_npc` - дойти до встречи.
- `spend_sunday` - завершить воскресный блок.
- `go_to_office` - выйти на работу.
- `work_monday_case` - пройти офисный кейс.
- `follow_monday_trace` - начать расследование следа во вторник.

Перед использованием флага проверь точное имя в Ink или Lua. Документ даёт карту смыслов, а не заменяет поиск по проекту.

## Карта

Актуальная логика карты связана с телефоном и map hub. Старый отдельный вызов карты не использовать.

Поддерживаемые сценарные задачи:

- открыть карту/хаб карты из Ink;
- разрешить отдельные точки;
- заблокировать отдельные точки;
- временно заблокировать все точки;
- ограничить карту одной точкой, если сюжет требует конкретного маршрута.

Примеры смыслов тегов:

- `# map:hub:some_knot` - открыть карту и после выбора/закрытия вернуться в нужный Ink-knot.
- `# map:allow:poi_id` - разрешить конкретную точку.
- `# map:lock_to:poi_id` - оставить доступной только конкретную точку.
- `# map:lock_all` - заблокировать все точки карты.
- `# map:allow:reset` - сбросить временные ограничения.

Перед использованием map-тегов для сценария смотри `INK_TAG_REFERENCE.md`. Сам `dialogue_manager_ink.lua` нужен только если меняется поведение тегов или есть подозрение, что справочник устарел.

## Лог диалога

В игре есть лог реплик. Он нужен, потому что на мобильном игрок легко может случайно прокликать текст.

Важное ограничение: лог не должен быть полноценным откатом истории. Игрок может перечитать, но не должен отменять сделанные выборы, получение предметов, переходы, флаги и последствия.

## Реклама

В Ink можно вызывать рекламу через поддерживаемый тег проекта. Перед использованием проверь точный тег в документации по Yandex SDK/рекламе проекта, чтобы не смешать его со старыми или тестовыми вариантами.
