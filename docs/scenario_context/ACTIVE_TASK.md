# Active Task Template

Этот файл можно копировать в GPT-проект и каждый раз обновлять под текущую задачу.

## Текущая задача

Коротко опиши, что нужно сделать.

Пример:

> Нужно написать сцену выхода из квартиры после утреннего диалога. После двери должна открыться карта в телефоне, где игрок выбирает место.

- Ink-файл:
- Knot/section:
- Scene Lua file, если есть хаб или хотспоты:
- Дополнительные source files, если нужны:
- Scene ID:
- Фон/скрин локации:

- Какие флаги уже выставлены:
- Какие предметы уже есть у игрока:
- Какие квесты активны:
- Какая сцена была перед этим:
- Какая сцена должна быть после этого:

## Что нельзя ломать

- Не менять старые knot names без необходимости.
- Не использовать старую отдельную карту, если нужна карта через телефон.
- Не давать игроку откатывать уже сделанные выборы.
- Не создавать новые системные теги без проверки кода.
- Не править GUI-файлы для обычных хотспотов.

## Какой результат нужен от GPT

Выбери один формат:

- Готовый Ink-фрагмент.
- Готовый Lua-блок хотспотов для `main/data/scenes/*.lua`.
- Список найденных проблем без правок.
- План сцены.
- Короткий пересказ сцены для документации.

## Проверка результата

Перед тем как вставлять ответ GPT в проект, проверь:

- Все `-> knot_name` ведут в существующие knot/stitch или в явно новые блоки, которые GPT тоже написал.
- Все `# tag` реально поддерживаются проектом.
- Все новые флаги имеют понятные имена и не конфликтуют со старыми.
- Hotspot `action` использует существующий тип: `goto_scene`, `ink_knot`, `set_flag`, `add_item`.
- Если это карта, используется актуальная карта в телефоне/хаб карты, а не старый вариант.
- Если задача использует теги, GPT видел `INK_TAG_REFERENCE.md`.
- Если GPT предлагает новый тег или меняет поведение старого, тогда нужен `main/scripts/dialogue_manager_ink.lua`.
