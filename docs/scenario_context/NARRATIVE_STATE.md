# Narrative State

Что важно понимать про state-систему проекта при написании сцен. Этот
документ — концептуальный. Реальный список существующих флагов / items —
в `PROJECT_INVENTORY.md` (автогенерируется из кода).

---

## Где живёт состояние

| Слой | Где | Что хранит |
|---|---|---|
| **Ink VAR** | `~ var_name = ...` в .ink файлах | Сценарные переменные, отношения, счётчики, выбранные варианты, gender/name |
| **Game state flags** | `gs.set_flag(...)` / `# set_flag:NAME=...` | Боевые флаги рантайма — читают сцены, хотспоты, телефон, инвентарь, scene_characters |
| **Inventory** | `gs.add_item(...)` / `# add_item:ID` | Предметы игрока |
| **Phone state** | `gs.add_sms/msg/mail/note/call/clue/...` | SMS, Messenger-чаты, mail, заметки, журнал звонков, улики, terminal |
| **Map state** | `gs.map_allow/lock_to/lock_all` | Доступность POI на карте |
| **Meta state** | `meta.inc/set` | Cross-loop счётчики, awareness, false_endings_seen |

Если AI пишет **только текст реплик** — обычно достаточно ink VAR + тегов. Если пишет **хаб с условиями** — нужны game flags + scene Lua.

## Имена и падежные формы

Игра ru-локализована, имена склоняются. В ink доступны заранее подготовленные формы для русского текста.

### Игрок (MC)

| Variable | Падеж | Артём | Мила |
|---|---|---|---|
| `mc_name` | именительный | Артём | Мила |
| `mc_name_gen` | родительный | Артёма | Милы |
| `mc_name_dat` | дательный | Артёму | Миле |
| `mc_name_acc` | винительный | Артёма | Милу |
| `mc_name_ins` | творительный | Артёмом | Милой |
| `mc_name_prep` | предложный | Артёме | Миле |

### NPC

| Variable | Падеж | (для male MC) | (для female MC) |
|---|---|---|---|
| `npc_name` | именительный | Мила | Артём |
| `npc_name_gen` | родительный | Милы | Артёма |
| `npc_name_dat` | дательный | Миле | Артёму |
| `npc_name_acc` | винительный | Милу | Артёма |
| `npc_name_ins` | творительный | Милой | Артёмом |
| `npc_name_prep` | предложный | Миле | Артёме |

### Правила использования

| Правильно | Неправильно |
|---|---|
| `{npc_name_gen} нигде не видно.` | `{npc_name} нигде не видно.` |
| `написать {npc_name_dat}` | `написать {npc_name}` |
| `рядом с {npc_name_ins}` | `рядом с {npc_name}` |
| `думаю об {npc_name_prep}` | `думаю об {npc_name}` |

Формы задаются в `00_bootstrap.ink`, инициализируются при выборе персонажа в `10_apartment.ink`, синхронизируются в `dialogue_manager_ink.lua` для совместимости со старыми сохранениями.

## Gender tokens

Для согласования глаголов с полом MC есть синтаксис:

```ink
Я почти не успел{mc_gender == "female":а|} начать волноваться.
```

- `mc_gender` — `"male"` или `"female"`, инициализируется в `choose_character`
- Условие в ink: `{mc_gender == "female": ...текст для женского...|...для мужского...}`

Также есть VAR `npc_gender` (зеркало). Используй когда нужно согласовать речь NPC по полу его персонажа.

## Сюжетные параметры (концепции)

В Ink можно встретить такие сюжетные характеристики:

- **Выбранный персонаж** (`mc_gender` + `mc_name`)
- **День истории** (sunday / monday / tuesday) — обычно отслеживается через флаги вида `sunday_finished`, `monday_*`, `tuesday_*`
- **TRUST** — уровень доверия NPC (увеличивается за внимательные диалог-выборы)
- **INSIGHT** — уровень наблюдательности / понимания происходящего
- **SYNC** — синхронизация с NPC / близость к петле

Точные имена variables / счётчиков смотри в текущем ink-файле перед добавлением новых. **Не создавай новые VAR если есть похожие**.

## Флаги — правила naming

Реальный список флагов с группировкой по префиксу — в `PROJECT_INVENTORY.md`. Несколько правил:

- **Префикс по локации/блоку**: `apartment_*`, `park_*`, `office_*`, `sunday_*`, `monday_*`, `tuesday_*`
- **Семантика суффикса**: `_done`, `_started`, `_seen`, `_active`, `_locked`, `_finished`
- **Specific feature flags**: `mug_taken`, `coffee_drunk`, `phone_taken`, `met_npc_sunday`

Перед добавлением нового флага проверь в `PROJECT_INVENTORY.md` секцию **Flags** — может уже есть подходящий, можно переиспользовать.

## Квесты

Квесты управляются ink-тегами `# quest:start:ID`, `# quest:done:ID`, `# quest:fail:ID`.

Существующие квесты — в `PROJECT_INVENTORY.md` (флаги типа `*_quest_*` или специальные имена).

Главные квесты-вехи: `find_phone`, `make_coffee`, `reply_npc`, `meet_npc`, `spend_sunday`, `go_to_office`, `work_monday_case`, `follow_monday_trace`. Имена могут эволюционировать — проверять актуальные в INVENTORY.

## Карта и Phone POIs

Карта — это часть телефона (не отдельный экран).

Управление картой из ink:
- `# map:hub:KNOT` — открыть карту в hub-режиме, выбор пина прыгает в `KNOT`
- `# map:allow:poi_id` — разрешить точку
- `# map:lock_to:poi_id` — оставить доступной только эту точку
- `# map:lock_all` — заблокировать все
- `# map:allow:reset` — снять временные ограничения

Список существующих `poi_*` — в `PROJECT_INVENTORY.md` секция **Phone Map POIs**.

## Лог диалога (backlog)

В игре есть read-only лог реплик (HUD-кнопка LOG). Игрок может **перечитать**, но **не должен откатывать** выборы / предметы / переходы / флаги.

Реализация: `main/scripts/dialogue_backlog.lua`. Записи добавляются при render каждой реплики, хранится в circular buffer.

## Реклама

В ink можно вызывать рекламу через теги:
- `# adv:fullscreen` — interstitial
- `# adv:rewarded:flag_name` — rewarded video, при просмотре ставит флаг

Подробнее — `YANDEX_SDK_AND_ADS.md`.

Не использовать legacy/тестовые имена тегов — только эти два.

## Cross-loop meta state

Часть состояния сохраняется **между итерациями** (петлями) для постепенного раскрытия мира:
- `iteration_number` — номер итерации
- `iteration_label` — форматированная (например `001`)
- `loop_awareness` — растёт со сценами осознания петли
- `false_endings_seen` — set ложных концовок которые игрок уже видел

Управление: `# meta:add:KEY:N` (для числовых), `# meta:set:KEY:VALUE`.

Эти переменные **не сбрасываются при reset_iteration**. Сбрасываются только через явный «начать с нуля» из меню.
