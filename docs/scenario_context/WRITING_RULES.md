# Writing Rules For GPT

Эти правила нужны для GPT, который помогает писать Ink, хабы и хотспоты.

## Главный принцип

Не изобретай новый рантайм. Используй только те механики, которые уже есть в проекте, или явно помечай, что предлагаешь новую механику, которую нужно реализовать в коде.

## Ink-правила

- Сохраняй существующие knot names, если нет отдельной задачи на переименование.
- Не создавай переход `-> some_knot`, если не пишешь сам `=== some_knot ===` или не уверен, что он уже есть.
- Не используй старый вызов карты. Для маршрутов нужна актуальная карта/хаб карты через телефонную систему.
- Если задача использует теги, сверяйся с `INK_TAG_REFERENCE.md`. `dialogue_manager_ink.lua` нужен только для изменения или отладки самих тегов.
- Теги пиши отдельными строками рядом с тем местом, где они должны сработать.
- Не добавляй флаги без понятного назначения.
- Не делай важные последствия только текстом. Если выбор должен влиять на игру, нужен флаг/переменная/тег.
- Не ломай `94_phone_mail.ink`: это заготовка под почту, её нельзя считать мусором.

## Выборы

Выборы должны иметь последствия, но лог диалога не должен позволять их откатывать.

Если игрок уже:

- выбрал маршрут;
- ответил в важной реплике;
- получил предмет;
- потратил предмет;
- изменил доступность карты;
- завершил сцену;

то это нельзя превращать в простой "откат назад". Лог нужен для чтения, не для отмены истории.

## Телефон и карта

Если сцена должна открыть карту из Ink, используй актуальные map/phone-теги проекта. Не описывай "открывается старая карта" и не предлагай отдельный устаревший экран.

Если нужно временно ограничить карту, используй смысловые операции:

- разрешить точку;
- заблокировать точку;
- заблокировать все точки;
- оставить только одну точку;
- сбросить ограничения.

Точные имена `poi_id` надо брать из текущих файлов телефона/карты.

## Хотспоты

Обычные хотспоты описываются в `main/data/scenes/*.lua`, а не руками в GUI.

GPT может предлагать готовый Lua-блок, но должен учитывать:

- координаты в 1280x720;
- `id` уникальный внутри сцены;
- `label` короткий и понятный;
- `action` использует поддерживаемый тип;
- `visible_when` только скрывает/показывает;
- `condition` блокирует действие, но может оставить хотспот видимым;
- `style` отвечает за внешний вид круга/иконки;
- `icon_offset` можно использовать, если иконка из шрифта визуально смещена.

## Стиль текста

- Пиши живой диалог, не объяснение лора.
- Давай конкретные детали локации.
- Не делай персонажей одинаковыми по голосу.
- Не перегружай сцену техническими словами.
- Не раскрывай тайну раньше времени.
- Помни, что игрок может проходить сцену на телефоне короткими сессиями.

## Склонение имён

Не подставляй `{mc_name}` и `{npc_name}` механически во все фразы. Эти переменные находятся в именительном падеже.

Если по-русски требуется другой падеж, используй готовые Ink-переменные:

- родительный: `{mc_name_gen}`, `{npc_name_gen}`
- дательный: `{mc_name_dat}`, `{npc_name_dat}`
- винительный: `{mc_name_acc}`, `{npc_name_acc}`
- творительный: `{mc_name_ins}`, `{npc_name_ins}`
- предложный: `{mc_name_prep}`, `{npc_name_prep}`

Примеры:

- `{npc_name_gen} нигде не видно.`
- `Можно написать {npc_name_dat}.`
- `Ты идёшь рядом с {npc_name_ins}.`
- `Говорить о {npc_name_prep} сейчас странно.`

Если фраза начинает звучать искусственно из-за подстановки имени, лучше переписать её без имени. Например, заменить `сообщение от {npc_name_gen}` на `сообщение в Messenger`, если имя уже понятно из контекста.

## Формат ответа от GPT

Лучший формат ответа:

- короткое описание, что меняется;
- готовый Ink или Lua-фрагмент;
- список новых/использованных флагов;
- список мест, куда это надо вставить;
- риски, если они есть.
