# Scenario GPT Context Pack

Эта папка нужна как компактный набор документов для GPT-проекта, который помогает писать Ink-сценарий, проверять логику сцен и достраивать хабы/локации/хотспоты.

Главная идея: не загружать в GPT все Ink-файлы, все фоны и весь проект сразу. Вместо этого сначала давать ему эти сжатые документы, а потом добавлять только те исходники, которые нужны для конкретной задачи.

## Что загружать в GPT почти всегда

- `STORY_BIBLE_SHORT.md` - короткая библия мира, тона и структуры игры.
- `WRITING_RULES.md` - правила написания Ink и запреты, чтобы GPT не ломал рантайм.
- `INK_TAG_REFERENCE.md` - поддерживаемые Ink-теги без необходимости грузить `dialogue_manager_ink.lua`.
- `INK_STRUCTURE.md` - какие Ink-файлы за что отвечают.
- `CURRENT_STATE_AND_FLAGS.md` - важные переменные, флаги, квесты и теги.
- `SCENE_SUMMARIES.md` - краткий пересказ уже существующих сцен.
- `HUB_AND_HOTSPOT_WORKFLOW.md` - как GPT должен помогать с локациями, хабами и хотспотами.
- `BACKGROUND_CATALOG.md` - какие фоны и scene_id уже есть.
- `SOURCE_FILE_PACKS.md` - какие реальные исходники докидывать GPT под разные типы задач.
- `ACTIVE_TASK.md` - шаблон текущей задачи.

## Если GPT пишет новую Ink-сцену

Дополнительно к базовому набору загрузи только 1-3 Ink-файла рядом с нужным местом истории.

Пример:

- Для воскресного утра: `01_apartment.ink`.
- Для свидания: `02_sunday_date.ink`.
- Для понедельника дома: `20_monday_home.ink`.
- Для офиса: `22_monday_office.ink`.
- Для телефона/SMS: `92_phone_sms.ink` и/или `93_phone_messenger.ink`.

Не надо каждый раз загружать все Ink-файлы. Чем меньше лишнего контекста, тем меньше шанс, что GPT начнёт путать сцены, старые теги и неактуальные решения.

## Если GPT помогает с локацией или хотспотами

Дополнительно загрузи:

- `HUB_AND_HOTSPOT_WORKFLOW.md`.
- `BACKGROUND_CATALOG.md`.
- Нужный файл из `main/data/scenes/`.
- Скрин/фон локации, если нужно расставить координаты.

Если GPT предлагает хотспоты, пусть отдаёт их как готовые Lua-блоки для `main/data/scenes/*.lua`, а не как правки GUI-файлов.

Важно: эти документы не заменяют живые исходники. Если GPT должен править конкретный exploration hub, ему всё равно нужны текущие Lua-файлы сцены и общий `_shared.lua`, потому что именно там лежат реальные стили, иконки, id сцен и условия.

## Если GPT помогает с проверкой логики

Дополнительно загрузи:

- нужный Ink-файл;
- `CURRENT_STATE_AND_FLAGS.md`;
- `SCENE_SUMMARIES.md`;
- при работе с картой или переходами - `HUB_AND_HOTSPOT_WORKFLOW.md`.

Проси GPT проверять не красоту текста, а конкретные риски: битые knot-переходы, забытые флаги, невозможные условия, старые теги карты, повторное получение предметов, нарушение порядка прохождения.

## Когда обязательно давать живые исходники

Документация в этой папке - это навигация и сжатый контекст, а не source of truth для кода.

Всегда докидывай исходники, если задача просит:

- изменить существующий hub или hotspot;
- добавить точный `rect`;
- использовать конкретный стиль круга или иконку;
- проверить, поддерживается ли Ink-тег;
- изменить карту, телефон, рекламу или переходы между Ink и GUI;
- проверить баг рантайма, а не просто написать текст.

Для точных наборов файлов смотри `SOURCE_FILE_PACKS.md`.
