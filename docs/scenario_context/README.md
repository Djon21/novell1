# Scenario GPT Context Pack

Папка для **AI-сценариста**. Компактный набор документов плюс автогенерируемый
снапшот состояния проекта. Чтобы AI помогал писать ink-сценарий и достраивать
локации/хотспоты/персонажей **без галлюцинаций** и без необходимости тащить
весь репозиторий в контекст.

## Главная идея

Не загружай все ink-файлы и весь Lua-код. Вместо этого:

1. **Базовый пакет документов отсюда** (≈9 файлов) — даёт AI понимание проекта
2. **`PROJECT_INVENTORY.md`** автогенерируется из реального кода → AI знает что **реально существует** в проекте (scene_id, knot имена, флаги, и т.д.)
3. **Source-файлы** даются только когда нужна точная правка конкретного слоя

С этим набором у тебя остаётся ~25-30 свободных slot'ов из лимита 40 для исходников под конкретные задачи.

## Базовый пакет (грузить всегда)

| Документ | Что внутри |
|---|---|
| `README.md` | Этот файл — общая инструкция |
| `STORY_BIBLE_SHORT.md` | Короткая библия мира, тона, структуры |
| `WRITING_RULES.md` | Правила Ink и запреты чтобы AI не ломал рантайм |
| `INK_TAG_REFERENCE.md` | Все поддерживаемые ink-теги с примерами |
| `STORY_MAP.md` | Карта сюжета по дням, структура `*.ink` файлов |
| `LOCATIONS_GUIDE.md` | Концепции хабов, хотспотов, фонов (как устроены) |
| `NARRATIVE_STATE.md` | Архитектура state, падежные формы имён, gender tokens |
| **`PROJECT_INVENTORY.md`** ⚡ | **Автогенерируется** — реальный список scene_id, knot, флагов, items, POI, фонов |
| `TEMPLATES.md` | Copy-paste блоки для типовых задач (новый knot/хотспот/сцена/scene_char/...) |
| `SOURCE_FILE_PACKS.md` | Какие source-файлы добавить под разные типы задач |

Итого: **10 документов** в базовом пакете.

Важно для file search: каноничные документы для AI-сценариста лежат именно в
`docs/scenario_context/`. Если поиск находит старые guides из `docs/guides/`
с verbose-hotspot формой, использовать их только как низкоуровочную справку,
а не как шаблон ответа. Для новых хотспотов канон: `LOCATIONS_GUIDE.md` +
`TEMPLATES.md`, формат через recipes.

## Workflow с AI

### Перед началом сессии

```bash
python tools/generate_scenario_inventory.py
```

Обновит `PROJECT_INVENTORY.md` под текущее состояние проекта (новые scene_id, knot'ы, флаги попадут в реестр).

### В сессии

1. Загрузить базовый пакет (10 документов выше)
2. Описать задачу
3. AI смотрит в **TEMPLATES.md** за паттернами + в **PROJECT_INVENTORY.md** за реальными ID
4. Если задача требует точной правки — AI запрашивает source-файлы через `SOURCE_FILE_PACKS.md`
5. Ты добавляешь нужные 1-3 ink/lua файла
6. AI выдаёт готовый код / ink — ты копируешь в проект и проверяешь

## Что AI должен делать

- **Брать паттерны из TEMPLATES.md** для типовых правок
- **Сверять имена с PROJECT_INVENTORY.md** перед использованием
- **Предлагать конкретные `id`, координаты, флаги** — не «потом сам подбери»
- **Запрашивать source-файл** если в INVENTORY не хватает деталей (`rect` хотспотов, существующие VAR, реальный visible_when, и т.д.). Триггеры — в SOURCE_FILE_PACKS.md и WRITING_RULES.md.
- **Соблюдать WRITING_RULES** — не создавать новые теги наугад

## Что AI НЕ должен делать

- Изобретать новые `action.type`, новые ink-теги, новые phone-apps (это код, не сценарий)
- Использовать `goto_scene` с несуществующим `scene_id` (проверять в INVENTORY)
- Создавать knot с дублирующимся именем (проверять в INVENTORY)
- Создавать новый ink-файл для маленькой сцены — добавлять knot в существующий
- Давать ответы вида «координаты потом подберёшь» — F1 editor существует для этого
- **Добавлять/менять `VAR`, падежные формы или стартовое состояние БЕЗ `00_bootstrap.ink` на руках.** Если задача задевает VAR — сначала запрос файла, потом правка.
- **Догадываться о состоянии bootstrap'а** (mc_name_*, npc_name_*, sunday_*, и т.п.) — список реальный, в файле.

## Когда обязательно давать source-файлы

Документация в этой папке — навигация и контекст, **не source of truth для кода**.

Всегда докидывай source если задача:

- меняет существующий hotspot (нужен точный `rect`)
- использует конкретный `STYLE_*` или иконку (нужен `_shared.lua`)
- проверяет поддержку нового ink-тега (нужен `dialogue_manager_ink.lua`)
- меняет карту / телефон / рекламу / переходы между Ink и GUI
- проверяет баг рантайма

Точные наборы файлов — в `SOURCE_FILE_PACKS.md`.
