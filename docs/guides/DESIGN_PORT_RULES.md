# DESIGN_PORT_RULES.md

Свод правил при переносе HTML/CSS-макетов в Defold GUI. Каждый пункт — **реальная грабля**, на которую уже наступали (ссылки на коммиты). Читать ПЕРЕД тем как начинать новый компонент.

---

## 0. Общий подход

- **Всегда читай исходный `*_mobile.html` целиком**, прежде чем писать `.gui`/`.gui_script`. Не переноси «по памяти/спеке» — реальный макет всегда богаче, чем словесное описание.
- Если `*_mobile.html` отсутствует — **спроси у пользователя**, не выдумывай по угадайке (это породило фейковый `phone_v2` в step8, потом пришлось переделывать).
- После каждого компонента: **визуальная проверка в Defold** + сравнение скриншотов с HTML-макетом. Без этого баги копятся и всплывают пачкой.

---

## 1. Альфа-наследование (inherit_alpha) — главная грабля

**Симптом:** компонент в коллекции «рендерится» (backdrop темнит экран), а всё содержимое невидимо.

**Причина:** в Defold `effective_alpha(child) = inherit_alpha ? parent.effective_alpha * child.color.w : child.color.w`. Если у контейнера `color.w = 0.0` и `inherit_alpha: true`, ВСЕ дети получают `alpha = 0`.

**Правила:**
- У «группирующих» нод (root-контейнеры типа `dlg_root`, `hud_root`, `opts_panel`) — либо `size = 0×0 + color.w = 1.0` (сам не рисует, но не обнуляет детей), либо у всех детей `inherit_alpha: false`.
- `backdrop` со своим `color.w = 0.55` (затемнение) НЕЛЬЗЯ наследовать — у детей modal/content ставь `inherit_alpha: false`, иначе они рендерятся на 0.55 от задуманной альфы и выглядят тусклыми/невидимыми.
- Если видишь «экран темнеет но модалки нет» — **первая проверка:** посчитай альфы всех родителей до корня, перемножь.

**Коммиты:** `2e4501b`, `5048df8`, `26c5113`, `de3de5f`.

---

## 2. Динамически создаваемые parent'ные ноды НЕ РЕНДЕРЯТСЯ

**Симптом:** `gui.new_box_node(...)` + `gui.set_parent(node, parent)` — нода enabled, alpha=1, координаты валидные, но невидима. Клики по ней работают (`gui.pick_node` пикает).

**Правило:** НЕ парентить динамически создаваемые ноды к «контейнерным» нодам. Создавай top-level + абсолютные координаты:

```lua
-- плохо (не рендерится):
local bg = gui.new_box_node(vmath.vector3(0, y_local, 0.63), size)
gui.set_parent(bg, gui.get_node("opts_panel"))

-- хорошо:
local bg = gui.new_box_node(vmath.vector3(PANEL_X + 0, PANEL_Y + y_local, 0.63), size)
-- no set_parent
```

Где `PANEL_X/Y` — абсолютные координаты контейнера, взятые из .gui-файла.

**Коммиты:** `4440f85`, `68c0c31`.

---

## 3. Z-порядок: внутри .gui vs между .gui-компонентами

**Внутри одного .gui-файла:** z работает нормально (выше z = поверх).

**Между GUI-компонентами в одном GO:** z **ИГНОРИРУЕТСЯ**. Порядок рендера определяется **порядком компонентов в GO**. Последний в списке — рисуется поверх.

**Правило порядка в `main_v2.collection`:**
```
1. main_menu_v2       (фулскрин меню, скрыто в игре)
2. dialogue_v2        (содержит scene_bg — фон комнаты)
3. hotspots_v2        (поверх фона; навигация между сценами тоже здесь)
4. hud_v2             (BAG/PHN баджи)
5. choice_v2          (модальные оверлеи)
6. inventory_v2
7. phone_v2
8. map_v2
9. effects            (scan/grain/vignette, самый верх)
```

Если меняешь порядок — проверь, не перекрыл ли важный контент.

**Коммиты:** `fc21c07` (hotspots нужно ПОСЛЕ dialogue_v2, чтобы не перекрываться scene_bg).

---

## 4. Z у динамических нод — ВСЕГДА явно

**Симптом:** dynamic node создана и не видна, но в списке enabled.

**Причина:** `gui.new_box_node(vmath.vector3(x, y, 0), ...)` — дефолтный z=0. Если статические ноды компонента имеют z>0 (например scene_bg z=0.06), динамика рисуется ПОД ними.

**Правило:** всегда передавай явный z в вектор позиции при создании.

**Коммит:** `30ab28e`.

---

## 5. msg.post не сериализует функции

**Симптом:** `ERROR:SCRIPT: unsupported value type in table: function`

**Причина:** scene_objects/hotspots в `scenes.lua` часто содержат `visible_when = function(gs) ... end`. Передаёшь такую таблицу в `msg.post` — падает.

**Правило:** перед `msg.post` очищай таблицу до сериализуемых полей:

```lua
local clean = {
    rect   = data.rect and { x=data.rect.x, y=data.rect.y, w=data.rect.w, h=data.rect.h } or nil,
    label  = data.label,
    icon   = data.icon,
    locked = data.locked and true or false,
}
msg.post(target, "set_hotspot", { index = i, data = clean })
```

Принцип: разрешены только `string`, `number`, `boolean`, `nil`, плоские таблицы из них, `vmath.vector3/4`, `hash`. Функции / userdata / upvalues / metatables — нельзя.

**Коммит:** `55d575f`.

## 6. Текстуры атласа: `play_flipbook`, не `set_texture`

- `gui.set_texture(node, "atlas_name")` — назначает ВЕСЬ атлас как ресурс (для use-цепочки).
- `gui.play_flipbook(node, "frame_name")` — показывает конкретный кадр/спрайт из атласа.

В `.gui` нода должна иметь `texture: "atlas_name"` (объявить атлас в `textures { name: "..." texture: "..." }` секции), а затем в скрипте `gui.play_flipbook(node, hash("frame_name"))`.

**Грабля-sentinel:** ink может вернуть `bg_name = "none"` — фильтруй:
```lua
if not bg_name or bg_name == "" or bg_name == "none" then return end
```

**Коммиты:** `96afd02`, `e70e52a`.

---

## 7. Defold-версия не поддерживает часть GUI-фич

Проверено на используемой версии:
- ❌ `TYPE_PIE` и поля `pie_fill_angle/piece_bounds/inner_radius` — парсер падает. Используй `TYPE_BOX` (для круглых кнопок — квадрат + бордер или спрайт).
- ❌ `gui.set_outline_alpha()`, `gui.set_shadow_alpha()` — функций нет в runtime. Объявляй `outline_alpha: 0.0` / `shadow_alpha: 0.0` прямо в `.gui`-файле.
- ❌ `script: ""` в .gui textproto — может ругаться. Если скрипт не нужен, удали строку полностью.

**Коммиты:** `894f2ea`, `2b37d9f`, `5b119e4`.

---

## 8. `acquire_input_focus` — на КАЖДЫЙ gui_script с `on_input`

Если у компонента есть `function on_input(self, ...)` — без `msg.post(".", "acquire_input_focus")` в `init` input не приходит. Не рассчитывай что сосед по GO «поделится» — Defold шлёт input только подписанным.

**Коммит:** `fc21c07` (F1 в hotspots_v2 не работал).

---

## 9. `gui.pick_node` работает даже для невидимых (disabled) нод

`pick_node` проверяет только геометрию + hierarchy, НЕ alpha и НЕ enabled-флаг. Поэтому:
- Если нода disabled — всё равно ловит клик. Обязательно проверяй `gui.is_enabled(node)` перед pick:
  ```lua
  if gui.is_enabled(node) and gui.pick_node(node, action.x, action.y) then ... end
  ```
- При переключении режимов (dialogue ↔ exploration ↔ modal) **явно скрывай** все интерактивные слои предыдущего режима: `msg.post(..., "hide_all")`.

**Коммит:** `55d08ee` (клики по диалогу промахивались на хотспоты).

---

## 10. URL / msg-адреса

- Компонентам в одном GO: `msg.url("#component_id")` — относительный.
- Скриптам-соседям: `msg.url("/go_id#script_id")` ЛУЧШЕ заменить на плейн-строку `"/go_id#script_id"` в константах — избегаешь пустого socket при lazy-eval.
- `msg.url(nil, "/music_player", "sound")` — **не работает**, socket пустой → `post()` падает. Используй `"/music_player#sound"`.

**Коммиты:** `3cb1f85`, `d7254da`.

---

## 11. Шрифты и иконки

- Все шрифты должны быть объявлены в `.gui` в секции `fonts { name: "..." font: "/path.font" }` ДО использования.
- Иконки: Material Icons шрифт → codepoints в UTF-8 байтах (например `\uE533` = inventory). Если в игре видны тильды `~` или квадратики — **codepoint отсутствует в атласе шрифта** (проверь, какие глифы зашиты при экспорте `.font`).
- Если в макете SVG-иконки — их **нельзя** переносить 1:1. Варианты: подменить на Material Icons codepoint, использовать TYPE_BOX-композицию, или вытащить PNG в атлас.
- Для адаптации к HTML-дизайну: составь табличку «SVG в макете → замена в игре» перед портом.

---

## 12. Текстовый контент и формат `.gui` textproto

- Defold Editor может пересохранить `.gui` и сломать ручное форматирование. Не правь длинные .gui вручную если проект открыт в редакторе.
- UTF-8 в `.gui_script` — всегда `utf-8` без BOM. Не давай Windows `CRLF`-драйверам перекодировать в cp1251 (старые файлы с тильдами — признак).
- `line_break: true` у текстовых нод — **обязательно** для многострочного контента, иначе текст режется по ширине без переносов.

---

## 13. Переходы режимов и очистка состояния

При переключении base_mode (menu/exploration/dialogue) или открытии overlay — **всегда явно скрывай** все конфликтующие слои:
- `show_dialogue` → `hide_nav`, `hotspots.hide_all`
- `show_menu` → скрыть ВСЁ кроме main_menu
- `show_exploration` → `hide_dialogue`, `show_hud`, `show_nav`
- `open_modal` → скрывать под ним только если модалка фулскрин-непрозрачная

Не рассчитывай что «если я ничего не послал, оно само скроется». Состояние липкое.

**Коммит:** `55d08ee`, `987e900`.

---

## 14. ADJUST_MODE и координаты

- `ADJUST_MODE_STRETCH` — нода масштабируется вместе с окном (позиции тоже).
- `ADJUST_MODE_FIT` / `ZOOM` — оставляют aspect; есть чёрные полосы / обрезка.
- `gui.get_screen_position(node)` возвращает координату в **реальных пикселях окна**, не в 960×640 базовом. Учитывай при абсолютном позиционировании.
- `pivot` меняет «якорь» позиции: `PIVOT_SW` — нижний-левый, `PIVOT_CENTER` — центр и т.д.

---

## 15. `max_nodes` в .gui

Default 512. Если плодишь динамику (например 8 app-tiles × 4 sub-ноды + 8 app-views × N контент-нод) — можешь упереться. Считай при проектировании, ставь с запасом.

---

## 16. Порядок шагов при порте нового компонента

Чеклист для **каждого** нового `xxx_v2.gui + xxx_v2.gui_script`:

1. Прочитай соответствующий `*_mobile.html` целиком.
2. Составь список нод: что статическое (в `.gui`), что динамическое (в скрипте).
3. Проверь шрифты/иконки — есть ли нужные codepoints, или нужно подменять на доступные.
4. Спроектируй иерархию с учётом правил alpha-inheritance (раздел 1).
5. Выбери z-значения в диапазоне, не конфликтующем с соседними компонентами (раздел 3).
6. Создай `.gui` со статическими нодами (root: `size 0×0, color.w=1.0`).
7. В `init` скрипта: `acquire_input_focus` (если есть on_input), get_node для всех нод.
8. Динамические ноды — top-level, абсолютные координаты, явный z (разделы 2, 4).
9. `on_message` — маршрутизация сообщений с проверкой типа.
10. `msg.post` наружу — только чистые сериализуемые данные (раздел 5).
11. Добавь компонент в `main_v2.collection` в правильной позиции (раздел 3).
12. Подключи обработчики в `ui_manager_v2.script` (show/hide, события).
13. Визуальный smoke-test в Defold — сравнение с HTML-макетом.
14. Commit + push, коммит с префиксом `v2(stepN): ...`.

---

## 17. Чего делать НЕ надо

- ❌ Не возвращайся к legacy GUI из `archive/legacy_runtime/main/gui/components/` — работаем только с `components_v2/`.
- ❌ Не меняй `bootstrap.main_collection` в `game.project`.
- ❌ Не добавляй emoji в код/комментарии если пользователь явно не попросил.
- ❌ Не коммить debug-принты в финальных фиксах (после того как баг локализован — уберить перед merge).
- ❌ Не используй `git add .` / `git add -A` без осторожности — тестовые флаги/артефакты могут попасть в commit.
- ❌ Не рассчитывай на то что Defold Editor «подправит» .gui при открытии — у автогенерации тоже есть баги.

---

## 18. Отладочная методология (когда что-то не работает)

Последовательность, которая работает:
1. **Включи enable=true принудительно** — если нода в коде должна показаться.
2. **Перекрась в яркий цвет** (magenta/green, alpha=1.0, size 960×640) — смотришь рендерится ли ВООБЩЕ.
3. **Лог `gui.get_screen_position`, `gui.get_color`, `gui.is_enabled`** для подозрительной ноды.
4. **Прогоняй по цепочке alpha от корня** — умножение может обнулить.
5. **Проверь z и порядок в коллекции** — возможно перекрыто соседом.
6. **Если pick_node работает но не видно — ровно alpha/z/parent issue.**
7. Логи с тегом `[compname]` (например `[phone_v2] tile 3 pos=...`), чтобы фильтровать.
